# Заметки по протоколу порта 20000 (живая колонка)

Замеры сделаны на SberBoom Mini (`sberboom-mini`, прошивка **1.104.35**, вендор SberDevices).
Транспорт — WSS `:20000`, TLV-конверт (Google proto-wire: varint / length-delimited), тот же,
что в HA-интеграции `sboom_ha`. Все запросы, кроме сопряжения, требуют PIN-токен
(`статус 4` без него).

## Сопряжение (важно)

| op | Смысл | Поведение |
|---|---|---|
| `4` | pair-init | Взводит сессию, ответ `{1: 1 (WAITING), 2: <session-uuid>}`. Колонка просит нажать **«+»** |
| `6` | pair-confirm | Приходит сам после нажатия: `{1: 1 (OK), 2: <token>}`. Токен — 36–40 символов |
| `5` | **pair-cancel** | Отменяет сессию **и инвалидирует выданный токен** |

Практика: одна отмена — и сохранённый токен перестаёт работать (проверено дважды:
после `op=5` GET_STATE с рабочим токеном вернул 44-байтовый кадр со `статусом 4`).
Поэтому после успешного сопряжения `op=5` слать нельзя; в обзорах операций
`op=4/5/6` нужно исключать.

Токен живёт и после закрытия сокета — повторное «+» не требуется.

## Ответы (с токеном)

| op | Размер | Содержимое |
|---|---|---|
| `1`, `2` | 44 б | `status=1`, пусто — служебные ack |
| `3` | 44 б | `{3: ''}` |
| `7` | 48 б | **`status=5`**, `{7: {1: 2}}` — единственный op, требующий параметр |
| `8` | 46 б | `status=1`, пусто |
| `9` | 46 б | `{9: {2: 1}}` |
| `10` | 774 б | GET_METADATA: `{1: 1, 2: {1: {1: fw, 2: model, 3: name, 4: vendor, 5: serial}, 4: '{"spaceshipLaunchUUID": …}'}, 3: <unix-ms>}` — **реквизиты самой колонки**, в HA не разбираются |
| `11` | 44 б | пусто |
| `12` | ~3570 б | GET_STATE: `{12: {1: '<json>'}}` — JSON целиком в поле 1. Ключи: `alarm`, `assistant`, `background_apps`, `current_app`, `deviceGroups`, `deviceSelector`, `deviceSleep`, `device_segments`, `homeSecurity`, `locale`, `location`, `morning_show`, `multiroom`, `network`, `proactivityNotification`, `reminders`, `sbercast`, `subscrDeviceInfo`, `time`, `timesync`, `user_settings`, `volume` |
| `17` | 131 б | Очередь: `{4: {0: 1}, 5: '[{"explicit":true,"trackId":…}, …]', 6: 0}` |
| `19` | 83 б | Спаренный BT: `{1: [{1: <mac>, 2: <name>}]}` — без признака «подключено» |
| `21` | 47 б | `{1: 1}` (скан BT) |
| `24…64` | 44 б | **все отвечают `status=1` и пустым телом** — роутер принимает, но без payload ничего не делает |

Вывод по `24…64`: коды существуют, но семантика вскрывается только фаззингом тел;
не делалось, чтобы не задеть сброс/обновление/калибровку.

## Фаззинг тел запросов (сделано)

Проверено 5 форм тела (`{1: 1}`, `{1: 0}`, `{1: {1: 1}}`, `{2: 1}`, `{1: "1"}`)
для `op=7, 8, 9` и `24…40`, с чтением GET_STATE после каждого запроса.

| op | Тело | Ответ | Вывод |
|---|---|---|---|
| `7` | любое из 5 | всегда `status 5`, `{7: {1: 2}}` | параметр не влияет — фиксированный отказ (не «нужен аргумент») |
| `8` | `{1: 1}` / `{1: 0}` / `{2: 1}` / `{2: {1: 1}}` | `status 1`, `{8: ''}` | на не-вложенное тело — пустой ack |
| `8` | `{1: {1: n}}` | `{8: {2: {1: n}}}` | **эхо**: возвращает ровно присланное, 50–52 байта. `{1:{1:1,2:1}}` → `{2:{1:1,2:1}}`, строка тоже возвращается |
| `9` | пусто | `{9: {2: 1}}` | константа |
| `9` | `{1: 1}` | таймаут → **устройство закрывает соединение** | неверный payload убивает сокет |
| `24…40` | `{1: {1: 1}}` | `44b status=1`, пусто | заглушек нет — операций не существует |

Побочных эффектов за весь фаззинг не было: громкость, будильники, `current_app`,
стереопара, multiroom и `sbercast` не менялись ни разу.

**Итог:** скрытых сеттеров (LED, будильники, мультирум, эквалайзер) на порту 20000 нет —
доступный набор это `op` 1–23 плюс утилитарные `3, 7, 8, 9, 11`. Единственное
пригодное к использованию — эхо `op=8`: в приложении на нём считается задержка
связи («Отклик, мс» в панели «Колонка»).

## Что из этого используется в приложении

- `Payloads.parseDeviceInfo` — модель/прошивка/вендор/серийник из `op=10` (точнее mDNS TXT).
- `Payloads.parseState` — raw-скан JSON внутри кадра (поле может быть любым).
- `Payloads.parseQueue` — `body[17][5]`.
- `Payloads.parsePairedBt` — `body[19][1]`.
- Тесты на реальных кадрах: `app/src/test/resources/metadata_10.hex`, `state_12.hex`
  (серийник заменён заглушкой той же длины — кадр остаётся валидным).
